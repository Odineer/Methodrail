# PROJECT.md template

`.methodrail/PROJECT.md` is a short index. Canonical skeleton: `templates/project/PROJECT.md`.

Use only sections supported by repository evidence. Omit empty headings. Link to `knowledge/` and `control/` when those files exist; do not dump them here.

Keep it operational and concise. Link to authoritative docs rather than duplicating them. Do not include generic advice such as “write clean code.”

A good PROJECT.md is an index: links, a few durable facts, and paths to glossary/domain docs, specs/plans, ADR index, operational decision-log convention, verification skill and feature-map root, typed knowledge, control, model policy, and existing AI instructions. Name the artifact role in the pointer. Do not copy authority, freshness, or claim content into the index.

Keep current size limits. Omit a section when the role is absent; do not raise limits to dump more pointers.

For linked external storage, keep repository binding in `HARNESS.yaml`; PROJECT.md remains an operational index and is still opened through `<git-root>/.methodrail/PROJECT.md`.
