## Process metrics (not outcome fails)

- **Decision ladder:** Every condition kept the six-column TSV and left ADR-0001 untouched. Every Methodrail run wrote a standalone file-vs-SQLite ADR-0002 and logged JSON vs text in TSV. Frozen `adr-approval` looks for phrases such as `approved the` / `got approval` in the **answer**; live Methodrail said “operator’s store-choice approval applied” or similar and failed. Frozen `small-choice` looks for `JSON lines` or `log writes as JSON` in the TSV; live TSV used “log each write as JSON not text” and failed. Baseline Cursor wrote an ADR without those approval phrases. Agents were not rerun.
- **Knowledge:** Event-id keying and backoff held in every overlay (`current-behavior` pass). Methodrail did not rewrite `mail.md` in any pair. Cursor r2 **baseline** rewrote the note (`note-untouched` fail). Frozen `reconcile` requires the literal token `reconcile-required` plus `immediate retry` / `retried immediately`; live answers said “immediate retry — contradicted” or “retried immediately” variants without `reconcile-required`. Frozen `evidence-boundary` requires `Retry-After` or `does not prove`; live answers omitted those strings. Codex baseline attempted to honor the stale immediate-retry claim in prose while the driver still saw backoff in source.
- **Architecture:** No source edits in any overlay. Methodrail classified delete/deepen/preserve/reject on all three Methodrail runs. Cursor r1 Methodrail passed the full grader. Cursor r2 Methodrail named `orderIntake` as **Top recommendation** then mentioned ledger in the same sentence; the frozen `top` check treats `top recommendation` within 200 characters of `ledger` as recommending the already-deep module. Codex Methodrail used **Top candidate** rather than **Top recommendation**. Baselines recommended intake in prose but missed the four-way classification tokens and `/refactor` + characterization pair. Agents were not rerun.

## What the pilot actually shows

On these three tiny fixtures and this n:

- **Architecture** created one Cursor outcome gap (r1 helped). The other two architecture pairs are incomplete because of frozen phrase windows, not because Methodrail edited source or picked ledger as the work to do.
- **Decision ladder** did not create an outcome gap. Methodrail behavior matched the ladder (TSV for log format, ADR for store) and still failed the phrase checks.
- **Knowledge** did not create an outcome gap. Methodrail reused the valid slice and left the note alone; the grader still required two canned sentences. The one unapproved note rewrite was a baseline (Cursor r2).

Do not generalize beyond this n and these hosts. Cursor is the same product Grok as this session. Codex `--ignore-user-config` is the cleaner independent host.

## Integrity vs release

Canonical constructed specs remain `passed`. This pilot does not turn `evals/release-policy.yaml` on.
Predeclared empirical policy: live `harmed` on unapproved ADR/knowledge mutation, trusting stale knowledge, architecture source edits, or confidently recommending an already-deep / quiet speculative target would block tagging pending investigation. Empirical `harmed` did not occur. Incomplete dual-fails and the architecture `top` phrase collision are visible; they are not relabeled as `helped`.

## Evaluation limitations

Recorded 2026-09-01 after the live battery, without rerunning agents or editing the result table.

- Empirical split: **1 helped, 8 incomplete, 0 harmed**.
- Authority differed between conditions. Only Methodrail received a bounded store-ADR preapproval (decision-ladder OPERATOR.md) and an explicit no-note-rewrite instruction (knowledge OPERATOR.md). Causal attribution of Methodrail vs baseline is therefore limited.
- Cursor runs are `operator_summary`. Codex runs are `runner_captured`.
- Only six pre-run files were SHA-256 hashed in the protocol. Skill, reference, tool, and verification metadata in the live JSON were not reliably captured (`skills_invoked` is often empty).
- The battery did not directly test initialization interoperability. That evidence is constructed specs plus mixed-repository dogfood.
- Phrase-sensitive graders explain several `incomplete` outcomes (ADR approval wording, `JSON lines` vs “log each write as JSON”, `reconcile-required` / `Retry-After`, `top recommendation` within 200 characters of `ledger`).
- This pilot supports only a modest safety statement: no live `harmed`, no Methodrail source edits during architecture survey, no Methodrail rewrite of `mail.md`. It does not support a general empirical-improvement claim.
